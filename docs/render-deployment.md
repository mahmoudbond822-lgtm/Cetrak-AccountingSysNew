# Render Deployment

This project deploys as two Render services plus one managed PostgreSQL database:

- `cetrak-api`: Django REST API from `backend/`
- `cetrak-frontend`: Vite static site from `frontend/`
- `cetrak-db`: PostgreSQL database used through `DATABASE_URL`

## Deploy From Blueprint

1. Push the repository to GitHub.
2. In Render, choose **New +** > **Blueprint**.
3. Select the repository and use the root `render.yaml`.
4. Fill the environment variables marked `sync: false`.
5. Deploy the blueprint.

## Required Environment Values

Set these values after Render creates service URLs:

- Backend `CORS_ALLOWED_ORIGINS`: `https://<frontend-service>.onrender.com`
- Backend `CSRF_TRUSTED_ORIGINS`: `https://<frontend-service>.onrender.com`
- Frontend `VITE_API_BASE_URL`: `https://<backend-service>.onrender.com/api/v1`

`DJANGO_SECRET_KEY` is generated by Render. `DATABASE_URL` is injected from the managed database.

If you add custom domains, add them to the same variables:

- Backend `DJANGO_ALLOWED_HOSTS`: `.onrender.com,api.example.com`
- Backend `CORS_ALLOWED_ORIGINS`: `https://<frontend-service>.onrender.com,https://app.example.com`
- Backend `CSRF_TRUSTED_ORIGINS`: `https://<frontend-service>.onrender.com,https://app.example.com`
- Frontend `VITE_API_BASE_URL`: `https://api.example.com/api/v1`

## Optional AI Key

Set backend `SYSTEM_DEFAULT_AI_KEY` only if the AI features should use a shared provider key. Leave it empty if users configure their own provider credentials in the app.

## Validation

After deploy:

1. Open `https://<backend-service>.onrender.com/api/v1/health/` and confirm `database` is `ok`.
2. Open the frontend service URL and confirm login/register pages load.
3. Register or log in and confirm browser network calls go to `https://<backend-service>.onrender.com/api/v1`.
